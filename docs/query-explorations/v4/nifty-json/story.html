How this experiment works

This describes our KeshavSoft learning implementation: how the shared JSON is represented, selected and changed in this playground.

01

Editor commands

The extension contributes commands to the editor command palette and context menus. Our lab models these as toolbar actions over one editable JSON source.

02

Path at cursor

A real extension can use the editor selection/cursor position plus a parsed JSON syntax tree to resolve the key under the cursor. Our lab currently selects a node in the structural tree and derives its JSONPath-like address.

03

Large files

A production large-file tree should parse lazily and expand children on demand. Our current lab renders a complete in-memory tree, so it is a behavior study, not a 512 MB performance clone.

04

JSONPath query

A query is evaluated against the parsed document and produces matches. We show each match with its path so it can be inspected or copied.

What we learned

The key lesson is that editor commands, document structure, and cursor position must be connected. A JSON editor should understand the document, not merely search its text.

Does it use Monaco?

Not a Monaco web app in the ordinary sense. Nifty JSON is a VS Code-family extension. It runs inside the host editor and uses the VS Code extension/editor APIs. Monaco is the browser editor component extracted from VS Code, but VS Code extensions do not automatically run inside a standalone Monaco instance.
