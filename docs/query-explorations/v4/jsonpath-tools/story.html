JSONPath language tooling

How this experiment works

This describes our KeshavSoft learning implementation: how the shared JSON is represented, selected and changed in this playground.

01

Language parser

A query should be parsed into a syntax representation. Diagnostics can then identify invalid syntax and unsupported constructs.

02

Data-aware completion

When the JSON document is available, object properties and array structure can inform completion suggestions.

03

Schema-aware completion

A JSON Schema can provide possible properties and documentation even when no concrete document is loaded.

04

Query execution

The same language definition should drive validation and execution. A separate ad-hoc parser risks accepting queries that the evaluator interprets differently.

What we learned

This project separates the query language from the JSON editor. We should treat JSONPath intelligence as a reusable language service, not a collection of input-box tricks.

Does it use Monaco?

No. The project documents a React editor component and a CodeMirror extension for JSONPath. Its npm package provides query evaluation and editor services. This is a useful reminder that JSONPath language intelligence is independent of Monaco.
