How this experiment works

This describes our KeshavSoft learning implementation: how the shared JSON is represented, selected and changed in this playground.

01

Source document

The JSON source is parsed into a JavaScript value for structural operations while the editable source remains the document the user works on.

02

Query mode

The query is evaluated against the current source. Results are presented separately so the user can inspect what was selected.

03

Apply result

A query result can become the new active document or be applied as a transformation. Our lab demonstrates the result-to-source workflow with an explicit Apply matches action.

04

Mode separation

Query, compare and schema are different tasks. Keeping them as modes/panels avoids mixing query controls into ordinary text editing.

What we learned

The important product idea is not just having a JSONPath input. It is the workflow between the original document, query results and the next editing action.

Does it use Monaco?

Yes. The project's documentation describes Monaco-based source editors and Monaco Diff Editor for compare mode.
