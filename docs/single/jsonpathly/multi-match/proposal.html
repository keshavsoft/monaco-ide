Multi-Match Proposal

This feature is for queries that return many results. It stays attached to the source JSON editor and does not become a separate search page.

V1

V1 is the basic result flow. The user types a query such as $.rawAst.program.body[*], executes it, and sees a result list on the right side.

This proves the idea: multi-match queries can be evaluated and displayed in a dedicated result area.

V2

V2 is where the real feature begins. The right side must stop being a plain result dump and become a match stepper.

The user must be able to move through matches one by one and understand which result is currently active.

This means the right panel becomes larger, the query input stays on top, and a small stepper appears when the result count is more than one.

Problem

Many results make it hard to understand which match is which and where each result comes from.

Goal

Provide a simple stepping experience for multi-result queries without leaving the editor flow.

Scope

This stays inside the feature folder and is only about multi-result queries and navigation.

V2 UX

  • Left side stays as the source JSON editor.
  • Right side becomes the larger result and stepper area.
  • Top of the right pane keeps the query input.
  • When the query returns many results, a compact match counter appears.
  • The user can move between matches with buttons or keyboard actions.
  • The active match is highlighted in the source editor and the result panel.

V2 behavior

The user types a query like $.rawAst.program.body[*]. The right pane shows the collection, and the stepper helps the user move through items sequentially.

Each step keeps the source editor synchronized to the current result. This is the real value of V2: multi-match browsing becomes understandable and traceable.

Design rule

This feature should look like an extension of the editor, not a separate dashboard. The right pane is larger than the autocomplete input area, but it still belongs to the same editor workflow.

The feature should remain narrow. It is not a general search product and it is not a full JSONPath runner page.

What V2 should do

V2 should focus on one thing: making multi-match results navigable and understandable inside the same editor workflow.

It is not a new app. It is a better result panel with stepping, synchronization, and clearer match tracking.
