The Evolution Story

Why We Built the "Single" Edition

While the full Monaco IDE grew into a comprehensive web-based development environment—complete with in-browser Service Worker HTTP virtual servers, virtual asset resolving, and multi-tab workspace sessions—many everyday workflows simply demanded a featherlight, focused editor.

When you want to tweak a configuration, craft a declarative JSON table specification, test a single HTML snippet, or edit a markdown doc, managing folder permissions and navigating deep folder structures is friction. The Single edition was created to solve this through progressive simplification:

1 V1: The Focused Core

Stripped out the virtual server and background service workers while keeping the explorer sidebar, quick open palette (Ctrl+P), and split preview.

2 V2: No Explorer

Eliminated the left workspace directory tree altogether. 100% of viewport width is dedicated to the Monaco Editor with direct file open (Ctrl+O).

3 V3: Strict Single File

Removed the multi-tab strip. Exactly one file in memory. Native disk persistence via Ctrl+S, active file status indicator, and instant split preview.

Declarative Architecture

Powered by Declarative DOM Primitive Bindings

Like all KeshavSoft projects, every Single edition adheres strictly to declarative separation of concerns:

1. bindings.json
Declarative map binding events (click, keydown) to named actions without imperative event loops.
2. actions.js
Pure, decoupled domain functions executed when events fire (e.g. togglePreview, saveCurrentFile).
3. eventBus.js
Asynchronous pub/sub broker allowing modules (header, preview, statusBar, tabs) to communicate cleanly without direct coupling.
